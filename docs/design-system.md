# TypeLoop design system

TypeLoopのUIは、タイピング中の集中を守り、結果を一目で理解でき、長時間でも疲れにくいことを最優先にする。既定の`noir`は白黒に近い静かな表現、`modern`は同じ構造のライト表現、`classic`は互換性を保つ従来表現である。

## 原則

1. **集中が主役。** 装飾は情報階層を助ける場合だけ使う。プレイ中は問題文、入力位置、残り時間の順に視線が流れるようにする。
2. **色ではなく役割で設計する。** コンポーネントは`--canvas`、`--surface`、`--content-*`、`--control-*`などのセマンティックトークンを使う。パレット名を直接使うのは既存スタイルの段階的移行に限る。
3. **モノクロでも意味が伝わる。** 選択、エラー、成功は色だけに依存せず、枠線、形、文言、状態属性を組み合わせる。ステータス色は意味のあるフィードバックに予約する。
4. **一貫した深度。** `canvas → surface → raised/inverse`の少数段階で奥行きを作る。強いグラデーションや過剰な影を重ねない。
5. **即時性を壊さない。** テーマ変更でReactツリーを分岐させない。ルート属性とCSSトークンで切り替え、入力処理やセッション状態に再描画コストを持ち込まない。

## トークンの責任

- `--canvas`: ページ全体の背景
- `--surface`, `--surface-inverse`: カードや反転面
- `--content-primary`, `--content-strong`: 本文と見出し
- `--content-secondary`, `--content-muted`: 補足情報
- `--control-primary`, `--control-on-primary`: 主要操作とその前景
- `--focus-accent`: キーボードフォーカスと選択状態
- `--accent-soft`: 控えめな強調。通常本文には使わない

生の色、影、角丸、余白、モーション、レイアウト閾値は`app/styles/themes.css`の`@tokens`レジストリだけに置く。コンポーネントやTSXへ値を直書きしない。`npm run check:tokens`がこの境界を検証する。

## テーマ要件

- 主要な本文・操作・反転面は全テーマでWCAG AA（4.5:1以上）を満たす。
- `color-scheme`をテーマに合わせ、フォーム部品やブラウザUIも不自然に反転させない。
- テーマはSSR時の`data-theme`で初期描画され、フラッシュを起こさない。
- 新しいテーマは許可リスト、設定ラベル、プレビュー、コントラストテスト、E2E永続化テストを同時に追加する。
- `noir`では純黒一色にせず、近接したニュートラル面で階層を作る。白は主要操作や最重要情報に限定する。

## インタラクションと性能

- 主要操作のタップ領域は44px以上。
- フォーカス表示を消さない。フォーカス順は見た目の順序と一致させる。
- モーションは160ms前後を基準とし、`reduced`設定では実質停止する。
- テーマ切替のための依存パッケージ、画像、ランタイム通信を追加しない。
- `backdrop-filter`は補助表現とし、読める背景色を必ず併記する。

## レビュー手順

変更時はデスクトップと390px幅でホーム、設定、プレイ、結果、履歴、辞典を確認する。キーボード操作、横スクロール、コントラスト、テーマ再読み込み、コンソールエラーを検証し、最後に`npm run check:ci`を通す。
